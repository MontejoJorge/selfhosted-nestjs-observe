# apps/web — agent guide

Vite + React 19 dashboard for the self-hosted `@nestjs/observe` collector. It only reads the
query API (`/api/*`) served by `apps/api`. Repo-wide rules live in the root [AGENTS.md](../../AGENTS.md).
Load the `react-best-practices` and `composition-patterns` skills before writing code.

## Stack

| Concern       | Library                                                                      |
| ------------- | ---------------------------------------------------------------------------- |
| Routing       | TanStack Router, file-based (`@tanstack/router-plugin`), typed search params |
| Server state  | TanStack Query (`queryOptions` factories, route loaders, suspense queries)   |
| Search schema | zod (`validateSearch`)                                                       |
| UI            | Tailwind CSS v4 (`@tailwindcss/vite`) + shadcn/ui (radix base, nova preset)  |
| Charts        | Recharts through shadcn's `ChartContainer` (`src/components/ui/chart.tsx`)   |
| Icons         | lucide-react                                                                 |

Maintainer decisions: TanStack for both routing and data fetching (no React Router), and the HTTP
layer will be replaced by a client generated with swagger-typescript-api from the API's OpenAPI spec
(it will land in `src/lib/api/generated`). Until then `src/lib/api/client.ts` is a deliberately
minimal `fetch` wrapper.

## Layout

```
src/
  main.tsx              providers: theme, QueryClient, tooltips, RouterProvider
  router.tsx            QueryClient + router (context, defaultPreload 'intent', pending/error components)
  routeTree.gen.ts      GENERATED by the router plugin. Commit it, never edit it.
  routes/               one file per route: search schema, loaderDeps, loader, component
  features/<area>/      queries.ts (queryOptions factories) + page and view components
  components/
    ui/                 shadcn/ui components (generated by the CLI, keep edits minimal)
    layout/             app shell, sidebar, service/range/refresh controls
    data/               tables, filters, badges, stat tiles, key/value lists
    charts/             TimeSeriesChart and the TimeBucket charts
    trace/              trace waterfall, span helpers, error panel
    page.tsx            Page, PageHeader, PageTitle, PageActions, PageSection
    states.tsx          PageSkeleton, ErrorState, EmptyState, NoTelemetryHint
  lib/
    api/client.ts       the only place that calls fetch (API_URL from VITE_API_URL)
    api/pagination.ts   infiniteQueryOptions helper for cursor `Page<T>` endpoints
    api/scope.ts        global Scope (service + range), time ranges
    scope-hooks.ts      useScope(): reads the root route's search params
    search.ts           zod helpers for search params
    format.ts           number, duration, byte, date formatting
```

## Conventions

- **Data flow.** Components and routes never call `fetch` (or the future generated client)
  directly. Each feature exposes `queryOptions`/`infiniteQueryOptions` factories in
  `features/<area>/queries.ts`. Query keys start with the area and include the scope and filters,
  e.g. `['requests', 'list', scope, filters]`. Swapping the HTTP client only touches `queryFn` bodies.
- **Loaders.** Each route declares `loaderDeps` (scope + filters from search) and its loader calls
  `context.queryClient.ensureQueryData(...)` (or `ensureInfiniteQueryData` for cursor lists). The
  component reads the same options with `useSuspenseQuery` / `useSuspenseInfiniteQuery`, so loading
  and error states come from the router's `defaultPendingComponent` / `defaultErrorComponent`.
- **Global scope.** `service` and `range` are validated in `routes/__root.tsx` and kept across
  navigation by `retainSearchParams`. Read them with `useScope()`. Page filters (`operationId`,
  `status`, `level`, `q`, ...) are declared in the page route's `validateSearch` and read with
  `getRouteApi('<id>').useLoaderDeps()`; update them with `navigate({ search: (prev) => ... })`.
  Free-text inputs use `DebouncedInput` so typing does not navigate on every keystroke.
- **Types.** Use `import type` from `@selfhosted-observe/contracts` (type-only package). Never
  redeclare API types in the app. Ask the backend owner to change the contract instead.
- **Empty states.** Every list handles "no data" with `EmptyState`; when nothing matches without
  filters, include `NoTelemetryHint` (tells the user to point `OBSERVE_ENDPOINT` here).
- **Composition.** Prefer small composable components (`PageHeader` + `PageTitle`, `StatGrid` +
  `Stat`, `KeyValueList` + `KeyValue`) and explicit variants over boolean props. Keep hooks and
  constants out of component files (fast refresh), e.g. `use-sorted-rows.ts`, `theme-context.ts`.
- **Charts.** One y-axis per chart (split measures into separate charts). Colors come from the theme
  tokens in `src/index.css` (`--chart-1..5`, `--status-ok|warn|error`, `--span-db|http|code`), which
  have light and dark values. Status colors always come with an icon or label.
- **Links.** Rows in tables are real links: put `<Link className={stretchedLink}>` in one cell of a
  `LinkRow`; other links in the row need `relative z-10`.
- **shadcn/ui.** Add components with `pnpm dlx shadcn@latest add <name>` from `apps/web`. Do not
  hand-write them.
- No tests (repo rule). Everything in English.

## Add a page

1. Add the query factory in `src/features/<area>/queries.ts` (stable key, `apiGet` in `queryFn`).
2. Build the page component in `src/features/<area>/<name>-page.tsx`. Use `useScope()`,
   `useSuspenseQuery(factory(...))`, `Page`/`PageHeader`/`PageTitle`, and an `EmptyState`.
3. Create the route file in `src/routes/` (e.g. `routes/<area>/index.tsx` for `/<area>/`,
   `routes/<area>/$id.tsx` for a param). Define `validateSearch` for page filters, `loaderDeps`,
   a `loader` that calls `ensureQueryData`, and `component`.
4. Run `pnpm --filter web dev` (or `build`) once so the plugin regenerates `routeTree.gen.ts`,
   then commit it with the route.
5. Add a sidebar entry in `src/components/layout/app-sidebar.tsx` if it is a top-level area.

## Commands

```sh
pnpm --filter web dev        # http://localhost:5173, regenerates the route tree on change
pnpm --filter web build      # tsc -b && vite build
pnpm --filter web typecheck
pnpm --filter web lint       # oxlint
```

`pnpm --filter @selfhosted-observe/contracts build` must have run once so the contract types exist.
